**S10 - Two agents answer at the same time.** Two agents of an invented site team each append an ACK on top of the same state. The first is accepted. The second submission is refused (local compare-and-swap on the shared branch; no remote, no network): the check passes only if the refusal is said in the first line with exit code 3 and the entry is not in the shared log. After a merge the entry is accepted: both consents count once, the proposal is ALIGNED, and the order of the entries is the order of the log (parents before children; between the two branches, the earlier commit time in UTC first), even though the merged document shows them in another order. Run: `python scenarios/S10_concurrent_entries/check.py` - last line `S10_concurrent_entries PASS` or `S10_concurrent_entries FAIL`. Inputs: `input/` (git history as fast-import streams, written by `scenarios/make_inputs.py`). Expected: `expected/declared.json` (written by hand in `scenarios/stories.py`) and `expected/gold*.json` (reference reducer). Everything here is synthetic.
